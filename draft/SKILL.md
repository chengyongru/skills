# Draft

Turn a `material` frame or raw input into paste-ready copy for the target platform.

1. Identify the source, audience, platform, and strongest verifiable fact; ask about the platform when it changes the result materially.
2. Read the matching reference: `references/hn.md`, `references/twitter.md`, or `references/longform.md`.
3. Build around a concrete observation and evidence. A useful default for engineering stories is problem -> investigation -> finding -> takeaway; adapt it to the material.
4. Write in an honest engineer's voice: specific, candid, concise, and proportionate to the evidence.
5. Preserve code names, commands, paths, API names, facts, and uncertainty. Flag `unverified` or `hypothesis` claims for the user's decision.
6. Keep only claims, transitions, and detail that carry evidence or meaning.
7. Return final copy ready to paste; put the primary language first for bilingual output.

Use `rewrite` afterward when the user wants voice matching or a selective polish pass.

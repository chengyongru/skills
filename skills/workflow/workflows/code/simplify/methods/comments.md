# No comments

Get a fresh comment review before applying accepted cleanup. Comment Sicko is the prompt at `references/comment-sicko.md`, not a registered agent type. The parent owns edits and verification; the child returns findings only.

## Scope

Use the caller's files or diff and allowed supporting reads. Otherwise identify the actual base branch, defaulting to `main` only when confirmed, and include the current working-tree diff without overwriting existing work. For PR review follow installed [pr-review](../../../pr/review/workflow.md); a review-only request does not authorize cleanup edits. Use installed [simplify](../workflow.md) for behavior-preserving implementation cleanup and [repo-prose](../../../writing/prose/workflow.md) for repository-facing comments/docstrings when applicable.

## Steps

1. Create a bounded native `subagent` task with the absolute `references/comment-sicko.md` path, runtime-reference path, repository/worktree, exact scope/head, allowed reads, and output limit. Require report-only behavior: no file changes, project scripts, external actions, or nested workers. Retain the returned task ID and await its report. Children inherit the configured model; a fresh perspective is not cross-model verification. If delegation is unavailable or prohibited, perform and label a direct review instead.
2. Inspect every finding against nearby code and its evidence. Reject scope escapes, unsupported deletions, and claims that useful correctness/safety rationale is redundant merely because it describes our own code. Preserve legal notices, API contracts, required directives, external constraints, regression rationale, and meaningful issue/RFC links. Uncertainty does not make a comment safe to delete. Use `$workflow how` or `$workflow why` on the scoped symbol when a thin `IMPORTANT` or `do not remove` claim needs grounding. A failed report may be retried once with the concrete failure named; a second failure stays open, not silently accepted.
3. For an editing request, apply only accepted, evidence-backed removals, corrections, or shortenings. A review-only request stops at proposals. Do not weaken lint/TypeScript suppressions automatically; understand their rule and behavior first. Fix trivial accepted implementation flags only when implementation changes are in scope, such as deleting a proven dead path, dropping an unused parameter, or using the real API.
4. If an accepted fix needs a new shape, run `$workflow architect` once for the accepted set and surrounding code, explicitly design-only. Then implement the smallest authorized root-cause fix. The [principle-fix-root-causes](../../../../principles/fix-root-causes.md) and [principle-redesign-from-first-principles](../../../../principles/redesign-from-first-principles.md) skills guide intent, not scope expansion. If the root cause is outside the fence, report it open and preserve necessary explanation rather than bolting on symptom guards or deleting its warning.
5. For genuine constraint comments, offer the cheapest in-scope type, runtime invariant, test, or CI lint that preserves the contract. Wait for approval if that encoding is outside the current authorization; unattended work needs pre-approval. If approved, encode and verify before removing prose made redundant. Otherwise retain the meaningful constraint and report the unenforced part. Never remove a protected requirement merely because it cannot be enforced here.
6. Run the repository's relevant lint/type/test command for actual changes and use the applicable native verifier for behavior touched. Report the scope, accepted/rejected findings, actual deletion count, preserved rationale, retries, design sketch, fixes, proposed/applied encodings, evidence, and open constraints. Do not commit, publish, widen the fix, or edit packaged skills/profile/memory automatically.

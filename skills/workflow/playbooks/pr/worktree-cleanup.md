### Worktree and simulator cleanup

**Inventory first. Delete only the exact resources the user explicitly approves.**

1. **Record the baseline without mutation.** On Windows use PowerShell filesystem/drive information, such as `Get-PSDrive -PSProvider FileSystem`, when space measurement is relevant. Locate the installed helper and run `python -B <plugin-root>/skills/workflow/scripts/workflow.py worktrees --repo <repo-path>` for a local read-only worktree inventory.
2. **Inspect each candidate.** Use the registered worktree paths, not guessed directory names. Record branch/head, tracked modifications, untracked and ignored files, upstream/ahead state, merge evidence against the actual intended base, and any known task/process ownership. `git status --short --untracked-files=all` does not show all ignored artifacts; inspect those separately when proposing removal. A branch can contain unpushed work even when its PR is merged. Do not fetch, scan private transcripts, or infer inactivity from timestamps alone.
3. **Confirm ownership and retention.** Ask the user about active or pinned work when available evidence cannot settle it. A sibling worktree may belong to an experiment or another agent. Unknown usage, untracked data, ignored data, missing upstreams, unpushed commits, and unrelated changes are hold reasons. Do not call untracked files "scratch" without owner confirmation.
4. **Present a deletion plan and obtain explicit approval.** List exact paths, branch/head, local data at risk, known use, preservation needs, and estimated reclaimable space. Name any branch refs, caches, simulator data, or runtime records separately; approval for worktree cleanup does not include them. Do not proceed merely because a row looks safe.
5. **Recheck, then perform only the approved non-destructive path.** Use installed [pr-worktree](../../workflows/pr/worktree/workflow.md) cleanup when available. It preserves changed, untracked, unpushed, and otherwise unsafe worktrees. If state changed after approval or the safe cleanup refuses, stop and report. Do not escalate to force removal, recursive directory deletion, hard reset, or automatic pruning. Destructive disposal or backup/move of held data requires its own exact approval and preservation plan.
6. **Verify the result.** Re-list registered worktrees and approved paths, confirm retained work is intact, and measure space using the same method as the baseline. Report estimates as estimates; do not claim reclaiming logical directory sizes as actual free-space gain.

For simulators and caches, inspect the actual installed platform/tools first. Do not assume macOS/Xcode commands exist on this Windows host. Inventory each resource and its user data, get explicit approval, then use the supported tool for only that resource. Never delete all devices, application state, package caches, or plugin/run history as a default reclaimer.

**Reply:** inventory and candidate paths, approval boundary, what was actually removed by the safe cleanup, before/after space when measured, and each retained item with its reason. An inventory-only request ends before deletion.

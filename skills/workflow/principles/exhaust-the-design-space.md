# Exhaust the Design Space

For a consequential novel interaction or architecture, compare two or three credible alternatives before committing to a shape. This also applies when product experience depends on feel rather than logic.

- State the decision and the evidence that will distinguish the alternatives. Use existing code or a small isolated prototype when that is enough; do not build three production implementations by default.
- Keep experiments inside the requested scope and a finite budget. Put scratch output outside live/shared state and the installed plugin. A read-only design review can compare proposals without writing code.
- Work serially or use a small permitted native fan-out with disjoint outputs. A no-subagent request wins.
- Present evidence and tradeoffs, then a recommendation. Ask the user to resolve preference choices.

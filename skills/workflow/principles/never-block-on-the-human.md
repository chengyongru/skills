# Never Block on the Human

Proceed without repeated permission questions for ordinary, reversible local work already covered by a clear request. "Reversible" is a risk property, not an authorization grant. A status question or read-only analysis does not authorize edits.

- Make reasonable implementation decisions inside the agreed scope, verify them, and present the result. Ask only when an essential fact, authority boundary, or user-owned decision is missing.
- Fix an in-scope blocker rather than asking whether to perform routine execution. Record unrelated bugs and follow-ups instead of expanding the task into self-healing work everywhere.
- Commit, push, PR creation, review/comment publication, merge, rebase/force-push, deploy, deletion, ticket mutation, and separate messages must fit actual user authorization, even when technically reversible. Never bypass a hook or approval gate.
- Do not edit protected profile/history/memory or a live plugin as an automatic lesson or repair. Use a task-owned external checkpoint when useful; a separately authorized package edit needs review and re-enabling.
- A no-subagent request prevails over workflow preferences. A long request remains bounded by actual runtime; timed work uses `cron` only at the requested cadence, and sustained goals require Goal Runtime Guidance.
- Product direction remains the user's decision. Offer a recommendation and continue independent safe work while a real gate is open; do not guess past it or claim unattended progress after the turn.

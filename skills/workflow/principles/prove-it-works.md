# Prove It Works

Check the real output: run the changed behavior, read the actual value, inspect the diff. File timestamps, cached screenshots, self-reports, and compilation alone cannot prove an unobserved runtime claim. When a check fails, examine both the observation method and the system rather than dismissing the failure.

Use the target project's verifier or [public verification](../workflows/verify/public/workflow.md). Exercise the changed happy path and highest-risk reachable edge through the supported interface; terminal behavior uses the supported terminal and launch path. For documentation, check actual instructions, links, contracts, and representative decisions instead of unrelated live/performance tests.

Reuse a deterministic check where useful. New scripts, live-state mutations, and publication still need appropriate scope. Bind results to the exact head or dirty snapshot and report actual commands, outcomes, gaps, and useful evidence outside the plugin. A worker stop claim needs current task/process evidence, not a cancellation request. Missing tools or required checks stay blocked or not run, never PASS.

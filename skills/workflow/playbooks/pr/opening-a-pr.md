### Opening a PR

Prepare a reviewable change; publish only when authorized. Confirm repository, branch, base, head, and dirty/untracked files. Use the [worktree lifecycle](../../workflows/pr/worktree/workflow.md) to reuse the branch's registered checkout when needed; honor an explicitly selected current checkout and preserve unrelated work. Keep coherent, ordered commits if committing is authorized. Apply scoped [simplification](../../workflows/code/simplify/workflow.md) and [repository prose](../../workflows/writing/prose/workflow.md), follow repository commands and hooks, and run its required checks plus [behavioral verification](../../workflows/verify/public/workflow.md). Record actual outcomes against the exact head or dirty snapshot. History rewriting needs separate authority.

Follow the repository's title convention, otherwise `type(scope): subject`. Keep the body a one-minute briefing, normally under 40 lines, with these `##` headings in order and empty sections dropped: `Why`, `What changed`, `Scope`, `Tradeoffs`, `Blast Radius`, `Verification`. Name the user problem, changed behavior, meaningful rejected alternatives, risks, and actual checks or gaps. Link detailed logs, measurements, and useful visual proof instead of pasting them. For a known Linear task, follow [Issue–PR relationship rules](../../references/linear-pr-links.md), include the appropriate magic word and clickable Issue link, and verify the effective relationship after publication.

If authorized, use installed GitHub guidance and `gh` with a body file, not shell built from untrusted text. Open completed work ready for review unless the user requests a draft; report incomplete work rather than marking it ready. A local commit grant does not grant push or PR creation. Stack follow-ups by base branch, with each child targeting its actual parent and one topology owner. Read back the published URL, state, base, and head. Otherwise leave the local diff, verification results, and proposed title/body for review. Opening a PR starts neither babysitting nor a review, schedule, auto-merge, or landing.
